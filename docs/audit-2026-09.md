## Decision: stay on Next.js
The site is already SSG per locale with a 40 ms TTFB and ~250 KB gzipped JS. The defects were CLS (preloader), canonical-host mismatch, raw Cloudinary videos, and content/i18n gaps. None are framework problems; Astro would not have fixed them.

## Dependency upgrade pass (2026-09-04, later the same day)

`bun update` moved next 16.2.6→16.3.4, next-intl 4.13→4.14.2, framer-motion 12.40→12.43, react 19.2.8, react-icons 5.6→5.7 (dropped `SiOpenai`), tailwind 4.3.3, eslint-config-next 16.3.4.

Applied, verified against the version-matched docs bundled in `node_modules/next/dist/docs` and next-intl's types:
- next-intl now reads the locale from `next/root-params` in `src/i18n/request.ts` (`requestLocale` and `setRequestLocale` are deprecated since 4.13.5). Layout uses `getLocale()`; page takes no params. /en and /es remain SSG.
- `reactCompiler: true` (stable in Next 16) with `babel-plugin-react-compiler`. Every component compiles except `Magnetic`, which opts out explicitly with `"use no memo"` (ref passed through `cloneElement`).
- Removed `experimental.optimizePackageImports` (measured byte-identical output) and the unused `ghchart` image pattern; dropped the redundant `--turbopack` flag; added `bun run typecheck`.
- Lint fixes for eslint-plugin-react-hooks 7.1: Header closes the menu via "adjust state during render" instead of setState-in-effect.
- Localized 404 now reachable via `app/[locale]/[...rest]/page.tsx`; invalid-locale paths still get Next's default 404.
- `alternateLinks: false` in routing (HTML already carries hreflang; the Link header disagreed on x-default).
- Hero image uses `preload` (Next 16 replacement for `priority`); `fetchPriority` alone made it lazy.
- Header logo offsets are per-locale CSS variables; "Código Por" no longer overlaps "Eugenio".
- Intro/hero timing: `IntroProvider` owns the intro state; the hero enters when the curtain lifts (no hardcoded 2.5 s), instantly on repeat visits, over a dark backdrop. This removed the white band at the top after the greeting.
- `next dev` appended the Next 16.3 agent-rules block to CLAUDE.md; keep it committed.

## GitHub section remake (2026-09-04)

Replaced the third-party ghchart iframe with a server-rendered section: `src/lib/github.ts` (server-only) fetches the contribution calendar and repo metadata via GitHub GraphQL when `GITHUB_TOKEN` is set, with public fallbacks (jogruber contributions API + unauthenticated REST) and a themed placeholder if everything fails. Fetches use `revalidate: 86400`, so /en and /es are now ISR (daily). `GitHubClient.tsx` renders a 53x7 heatmap in the site palette, a stats row (contributions, active days, busiest day, private-work share), and four curated repo cards, animated with the Tech Stack stagger pattern. Verified: no secrets in the client bundle, build passes without a token, both locales translated, Lighthouse mobile 90 / 100.
