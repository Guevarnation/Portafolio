## Decision: stay on Next.js
The site is already SSG per locale with a 40 ms TTFB and ~250 KB gzipped JS. The defects were CLS (preloader), canonical-host mismatch, raw Cloudinary videos, and content/i18n gaps. None are framework problems; Astro would not have fixed them.

## Round 3 — performance + layout (2026-09-04, evening)

Measured first. Lighthouse 12 (bunx, headless Chrome, this machine) against the live site before any change:

| Live, before | Mobile | Desktop |
|---|---|---|

| LCP | 1.39 s (hero `<img>`; TTFB 197 ms, **resource load delay 767 ms**, load 57 ms) | 0.72 s (load delay 118 ms) |
| FCP / SI / TBT / CLS | 1.12 s / 5.5 s / 20 ms / 0.010 | 0.33 s / 1.66 s / 0 ms / 0.002 |
| JS transfer (initial) | 297 KB gz in 9 chunks | same |

The owner's PSI report (perf 74, LCP/redirects/preconnect/etc. red) is a different lab: PSI runs from a remote region against the apex URL, so it pays apex→www→/en (two redirects) plus a long RTT. What the data actually said:

- **Redirect chain:** `https://eugenioguevara.com` 308 → `www` 307 → `/en`. Only the second hop is ours.
- **LCP** is the hero image on both form factors. It was *discoverable* (preload link present) but requested at priority **Low** on mobile — Lighthouse: "fetchpriority=high should be applied". The image bytes are tiny (6 KB webp at 750w, 24 KB at 1920w), so AVIF (`images.formats`) would not move anything and was **not** added: it only adds encode latency on the first request per size.
- **Preconnect:** no origins preconnected; `res.cloudinary.com` (posters + videos) is the only third-party origin.
- **Unused JS (81 KB):** all in vendor chunks (next runtime 55 % unused, react-dom 33 %, gsap+motion+intl-messageformat 39 %). App code is one 62 KB gz chunk; the only removable part of the initial bundle is below-the-fold islands.
- **Image delivery / next-gen formats:** every flagged item is a Cloudinary `so_0,q_auto,w_1200/*.jpg` poster from Projects (1200 px served for 370–700 px slots, no `f_auto`) plus `micontax.jpg` at `w=1200`. Owned by Projects — see follow-ups.
- **HTML** is 234 KB (51 KB gz): TechStack inline SVGs 107 KB, GitHub heatmap 68 KB. Gzip removes most of it (heatmap `title`s cost 2 KB gz), so it was left alone.

### Changed
- `localePrefix: "as-needed"`: English at `/`, Spanish at `/es`, `/en/*` 307s to the unprefixed path. `SITE_URL` + `localeUrl()` in `src/i18n/routing.ts` feed canonical, hreflang (en, es, x-default → `/`), `og:url`, sitemap and robots. The proxy matcher now skips `*opengraph-image` so `/en/opengraph-image` (what Next writes into `og:image`) returns the PNG directly instead of 307 → `/opengraph-image`.
- Hero `<Image>`: `preload` + `fetchPriority="high"` (Lighthouse now reports "fetchpriority=high applied"; the `<link rel=preload imagesrcset>` carries it too).
- `preconnect` for `https://res.cloudinary.com` via `react-dom` in the layout (documented approach in generate-metadata.md; the Metadata API has no field for hints). A `prefetchDNS` for the same origin was tried and removed: React emits no `dns-prefetch` link when a `preconnect` for that origin exists.
- Lazy-loading below-the-fold islands: measured and **not kept**. (a) `next/dynamic` for TechStack from `page.tsx` (a Server Component) split a 31.6 KB gz chunk but still shipped it as an initial `<script async>`, exactly as lazy-loading.md warns. (b) A Client Component wrapper (`GitHubIsland.tsx`, `next/dynamic` with SSR kept) did defer GitHubClient (5 KB gz) but Turbopack then split the modules shared with TechStack into four more chunks: 12 requests / 293.8 KB instead of 8 / 290.0 KB, LCP and TBT unchanged within noise. Reverted; the remaining initial JS is 80 % vendor (next runtime, react-dom, gsap + motion + intl-messageformat).
- Seamless GitHub → Contact: `.dark` wrapper in `page.tsx`/`page.module.scss` is the backdrop for TechStack + GitHub + Contact; both sections are transparent, GitHub keeps `position: relative; z-index: 1`, and its card surfaces are opaque `#1b1c1d` so the Contact title shows in the card gaps but not through the cards. Verified with headless screenshots at 1440 and 390 (`scrollY` = repos −200 / 0 / +300 / +600 / +900).
- Preloader greeting `<p>` is centered with `transform: translate(-50%, -50%)` instead of flex alignment: each word has a different width and the re-centering produced six layout-shift entries per intro (0.0096 of the 0.0099 mobile CLS).

## Round 4 — verifier fixes (2026-09-04, night)

Contact form hardening and the zod bundle regression flagged by the round-3 verifier.

- **zod no longer ships to the browser.** `src/lib/contact-types.ts` (zod-free: `CONTACT_LIMITS`, `MIN_FILL_MS`, `MAX_FORM_AGE_MS`, the `ContactField`/`ContactErrorCode`/`ContactState` types, `initialContactState`) is what `ContactForm.tsx` imports. `src/lib/contact-schema.ts` keeps the zod schema behind `import "server-only"` (package added), so a future client import fails at build time. Verified after `next build`: `grep -l _zod .next/static/chunks/*.js` matches nothing; initial JS is back to the pre-form footprint (numbers below).
- **Fill-time check is no longer bypassable by omission.** `startedAt` must be a 13-digit epoch string and the form must be 3 s – 24 h old; a missing field, `""`, `0` or garbage is rejected (`Number("")` was `0`, which passed). It stays client-supplied and unsigned, so it is a speed bump, not proof of humanity.
- **Rate limiting.** Per-IP in-memory limiter (5 send attempts / 10 min, keyed by `x-forwarded-for` via `headers()`) returning the new `rateLimited` code (EN + ES). It only counts attempts that reach Resend, and it is per-instance on Vercel, so the durable control is a WAF rate-limit rule the owner adds in the dashboard; residual risk documented in `.env.example`.
- Honeypot renamed `company` -> `contact_extra` (address autofill can populate an off-screen "company" field) and a server `console.warn` on hits so silent drops are observable.
- Form a11y: `noValidate` so every error is the translated server message; inputs are `readOnly` (not `disabled`) while pending so focus is not dropped; after the action settles focus moves to the first `aria-invalid` field or the status region (`tabindex=-1`); the submit label is a `<span>` (phrasing content inside `<button>`).
- Posters: served at `w_800` max (measured YEYAR poster 60 KB -> 32 KB webp); the video keeps `w_1200`. YEYAR intrinsic size corrected to 1200x752 (Cloudinary rounds video heights to even numbers).
- `localeUrl("en")` returns the bare origin, so canonical, hreflang, `og:url`, sitemap and JSON-LD agree. `prefetchDNS` removed (see round 3 note).

Not changed, with reasons:
- Footer EN link `href="/en"` (307 -> `/`): required. With `localePrefix: "as-needed"` next-intl's middleware resolves an unprefixed request from the `NEXT_LOCALE` cookie before `Accept-Language` (`middleware/resolveLocale.js`), so a plain `<a href="/">` clicked from `/es` with the `es` cookie would bounce back to `/es`. The `/en` hop is what rewrites the cookie.
- `micontax.jpg` `sizes`: at 412 px / DPR 1.75 the slot is 372 CSS px -> 651 device px, so the 750 candidate is the correct pick; the remaining Lighthouse "waste" is its compression estimate.
- Localized 404 still renders in Next's error shell; unchanged from live.

Owner actions: Vercel WAF rate-limit rule for POST `/` and `/es`; verify the domain in Resend and set `RESEND_FROM` + `RESEND_API_KEY` (Production + Preview); submit the live form once and confirm delivery and reply-to.

- Contact parallax lift reduced from 500 px to 200 px (80 px on mobile) so its title never slides up behind the GitHub repo cards; only the dark top padding overlaps the card gaps.
